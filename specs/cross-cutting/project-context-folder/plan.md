**Status:** done

## Context

The shipped v0.1 "Project Context Folder" feature (`server/src/modules/context-docs/`) discovers repo-relative `.md` files via an **include-glob allow-list** (`repos.context_search_globs`, default `**/{specs,docs,insights}/**/*.md`, matched via `micromatch`). This revision flips the model to a **gitignore-style exclude-list**: the walk still visits every `.md` file in the clone (unchanged cost — spec's own AC-1 note), but the post-walk filter now *removes* paths matching configured exclude patterns instead of *admitting* paths matching configured include globs. An unconfigured repo (`null`) now excludes agent-instruction files by default (`**/AGENTS.md`, `**/CLAUDE.md`, `**/.claude/**`, AC-43); an explicitly persisted empty array (`[]`) means zero exclusions — scan everything. Exclude-pattern matching must use real gitignore semantics (wildcards, `**`, anchoring, `!` negation, AC-44) — the existing `micromatch` flat-glob matcher has no negation/anchoring precedence concept, so this revision adds the `ignore` npm package (same library ESLint/Prettier use), per the spec's own recorded implementation recommendation (§13 Clarifications Log #7).

**Own-research finding, not in the task brief:** repo-wide grep (`grep -rln "from 'micromatch'"`, excluding `node_modules`) shows `micromatch` is imported **only** in `server/src/modules/context-docs/reader.ts` — nowhere else in `server/`, `client/`, `reviewer-core/`, `e2e/`, or `mcp-server/`. Once WI-5 below replaces its one use with `ignore`, `micromatch`/`@types/micromatch` have zero remaining call sites repo-wide. This contradicts the task brief's inherited assumption ("micromatch stays a dependency for other unrelated uses in this module/repo — don't remove it"); this is a codebase fact resolved as an implementation-approach detail, not a requirements question, and is flagged in WI-1 for the implementer to re-confirm (in case their own edit leaves an incidental use) before deciding whether to drop the dependency.
